## 1. Настройка «Пружинные анимации во всей системе» в Панели задач

Появился единый системный переключатель пружинной физики, доступный сразу в двух местах:

- **Настройки → Панель задач** (блок **«Авто-скрытие шума, Магнитный Dock и Пружинные анимации»**): главный тумблер **«Пружинные анимации во всей системе»** с индикатором статуса `Пружины: ВКЛ / ВЫКЛ`.
- **ПКМ по самой панели задач:** быстрый пункт **«Пружинные анимации [ВКЛ / ВЫКЛ]»** для мгновенного переключения прямо с рабочего стола.
- **Глобальное действие на всю ОС:** настройка сохраняется в `localStorage` (`luma_spring_animations_v1`, по умолчанию включена) и синхронизируется с атрибутом `data-spring-physics="on | off"`. При отключении мгновенно переводятся на быстрые линейные переходы без отскока:
  - физика инерции перетаскивания и плавного разворачивания/прилипания окон `DexWindow`;
  - пружинный отскок запуска и кривая притяжения иконок магнитного `Dock`;
  - всплывающие меню Пуск, Центр управления, Панель управления, контекстные меню ПКМ (`SmartContextMenu`) и панель `Luma Nova`;
  - плавное скрытие/появление панелей в полноэкранном режиме и резиновая анимация `Dynamic Island`.
- Полная совместимость с режимом «Без анимаций» (`data-anim="none"`).

## 2. Критические исправления багов ядра `LumaCore 1.5.5` и ОС

### 2.1. Многопальцевые жесты Precision Touchpad (`Win32 Raw Input HID`)
При глубоком аудите нативного HID-драйвера (`kernel_touchpad_rawinput_win.go`) были обнаружены и устранены три реальных сбоя на ноутбуках с Windows Precision Touchpad:
- **Исправлено сопоставление `HIDP_VALUE_CAPS` при `IsRange == 0`:** на большинстве контроллеров Precision Touchpad оси `X`, `Y` и `ContactCount` объявлены как одиночные `NotRange`-значения (где `UsageMin == Usage`, а `UsageMax == 0`). Прежняя проверка `UsageMin <= usage <= UsageMax` давала `false` на реальном железе; добавлена корректная функция `tpValueCapMatchesUsage`.
- **Сбор всех контактов с учётом `LogicalMin` и `TipSwitch (0x0D/0x42)`:** драйвер теперь читает координаты всех логических коллекций пальцев, вычитает `LogicalMin` при нормализации и проверяет реальное касание `TipSwitch` через `HidP_GetUsages`.
- **Поддержка гибридных тачпадов ELAN / Synaptics / Intel и гарантированное завершение жеста:** устранён ложный сброс трекинга на продолжениях пакета (`ContactCount == 0` при активном `TipSwitch`), добавлено экспоненциальное сглаживание координат и встроен таймер `WM_TIMER` (`80 мс`) в существующую единственную процедуру окна `tpRawInputWndProc` (без создания новых `syscall.NewCallback`), чтобы жест гарантированно срабатывал даже на контроллерах, не отправляющих финальный пакет с 0 контактов.

### 2.2. Физика окон `DexWindow` и магнитный `Dock`
- **Плавное пружинное разворачивание и восстановление окон:** режим `maximized` в `DexWindow` переведён с CSS `right/bottom` на явные числовые `left/top/width/height` с отслеживанием `window.resize`, благодаря чему окна плавно разворачиваются и сворачиваются с пружиной вместо мгновенного скачка.
- **Актуальный отступ верхней панели:** добавлен `topBarOffsetPx` в зависимости обработчика drag/resize `DexWindow` (устранён сдвиг границ после переключения режима двойной панели задач).
- **Устранена обрезка магнитного `Dock`:** контейнер вкладок панели задач теперь использует `overflow-visible` при количестве элементов `≤ 9`, поэтому увеличенные иконки при наведении, пружинный отскок (`-13px`), бейджи и светящийся ореол прогресса больше не срезаются по вертикали.
- **Сброс залипших трансформаций и защита отскока:** при выключении магнитного режима все inline-трансформации иконок мгновенно сбрасываются, а движение курсора больше не перезаписывает активную анимацию отскока запуска (`.luma-dock-bounce`).

### 2.3. ИИ-шлюз `Luma Ai Nitrogen`, генератор PowerPoint и консоль OTA
- **Изоляция API-ключей облачных провайдеров ИИ:** при переключении в `Luma Ai Nitrogen` с локального `Ollama` на облачный провайдер (`Google Gemini`, `OpenAI`, `DeepSeek`, `Groq`, `OpenRouter`, `Claude`) сохранённый локальный ключ `"ollama"` больше не подставляется в облачный запрос при пустом поле ключа — система сразу выводит понятное предупреждение об отсутствии API-ключа.
- **Исправлена ошибка форматирования в `kernel_ai_38.go` (`go vet`):** экранирован символ `%` в шаблоне `fmt.Sprintf` генератора слайдов PowerPoint (`+35%% скорости` вместо неверного спецификатора формата). Проход `go vet ./...` завершается полностью чисто (0 ошибок, 0 предупреждений).
- **Консоль обновления `Luma Update Cinema`:** исправлен сброс живого графика скорости (`SVG sparkline` больше не сохраняет старые демо-точки при реальных обновлениях) и выровнены данные всех 5 этапов предварительного просмотра под `1.6.5`.
